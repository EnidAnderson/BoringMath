## Station entries

### F4. Nisnevich topology — the nearest door

- NEEDED-BY: A¹-localization, motives with transfers, cdh/Nisnevich descent
  (the dictionary's "environmental layer").
- NAIVE FORM: Nisnevich coverings as point-set conditions checked by hand.
- RIGHT HOME: a Grothendieck topology on the small étale site generated by
  distinguished squares — i.e., as DATA, sitting on the existing
  cd-flavored infrastructure.
- EXTRACTION: distinguished-square sieve membership lemmas; the point-set
  criterion a corollary.
- MATHLIB: GOLD. `Mathlib/CategoryTheory/Sites/MayerVietorisSquare.lean`
  (Riou; read in full this audit): `GrothendieckTopology.MayerVietorisSquare`,
  sheaf conditions, gluing, the short exact complex of free abelian sheaves.
  Its docstring names Nisnevich distinguished squares as the motivating
  example and leaves the long exact sequences as TODO.
- MINIMAL API (predicted new modules, never in-place extension):
  - `Mathlib/CategoryTheory/Sites/CdStructure.lean` — topologies generated
    by classes of squares (anchor: Voevodsky, *cd-structures and Nisnevich
    topologies*, 2010). Deps: `Sites.Grothendieck`,
    `Sites.MayerVietorisSquare`.
  - `Mathlib/AlgebraicGeometry/Sites/Nisnevich.lean` — the Nisnevich
    distinguished squares as `MayerVietorisSquare`s on the small étale
    site; the generated topology. Deps: `AlgebraicGeometry.Sites.Etale`,
    `Sites.MayerVietorisSquare`.
- FIRST SHARDS: (a) the definition of a distinguished square on schemes,
  statement-only (Tier 1); (b) an étale morphism iso over the closed
  complement ⟹ MV-square (Tier 2, moderate).

### F6. Finite correspondences, transfers, PST — green-field

- NEEDED-BY: presheaves with transfers, Voevodsky motives, P¹-motives; the
  transfer layer of the dictionary.
- NAIVE FORM: transfers as functions on point-sets; correspondence
  composition as an operation on functions.
- RIGHT HOME: the category `SmCor` of smooth schemes and finite
  correspondences as a `Category` with spans-with-finite-support as
  morphisms (anchor: Mazza–Voevodsky–Weibel, *Lectures on Triangulated
  Categories*, ch. on correspondences); then presheaves with transfers as
  additive presheaves on it.
- EXTRACTION: the induced function on points is a lemma about graphs, not
  a foundation.
- MATHLIB: ABSENT (BRONZE: scoped searches for
  `withTransfer`, `with transfers`, finite correspondence constructs — 0).
- MINIMAL API:
  - `Mathlib/AlgebraicGeometry/Correspondences/Basic.lean` — spans with
    structure. Deps: `CategoryTheory.Arrow`, limits.
  - `Mathlib/AlgebraicGeometry/Correspondences/Finite.lean` — finite
    correspondences over smooth schemes; identity and composition.
    Deps: `AlgebraicGeometry.Morphisms.{Smooth,Etale}` (F2), finite
    limits of schemes.
  - `Mathlib/AlgebraicGeometry/Motives/PresheafWithTransfers.lean` —
    the additive presheaf layer. Deps: correspondences, `Sites.Abelian`.
- FIRST SHARDS: the correspondence structure and its identity/composition
  laws, statement-only, then peeling (Tier 1–2, several PRs).

### F10. Spectra, stable ∞-categories — the deepest hole

- NEEDED-BY: S∞, SH(k), A¹-localization, six functors; the stable home of
  the whole program.
- NAIVE FORM: spectra as graded homotopy sets with structure; triangulated
  homotopy categories taken as primitive.
- RIGHT HOME: sequential spectra over a model category; stable model
  structures; stabilization as a localization; the triangulated shadow
  extracted as homotopy-category theorems (anchor: Hovey, *Model
  Categories*; Lurie, *Higher Algebra*).
- EXTRACTION: homotopy-category lemmas; the classical triangulated
  structure of F7 is the extracted shadow, not the foundation.
- MATHLIB: ABSENT at the pin (BRONZE). But more scaffolding exists than
  the program assumed: model categories (F8) and quasicategory basics (F9)
  are real. The triangulated 1-categorical machinery (F7) exists and is
  bare-bones, as expected.
- MINIMAL API (staged, honest):
  - `Mathlib/AlgebraicTopology/Spectra/Sequential.lean` — sequential
    spectra in a model category. Deps: `AlgebraicTopology.ModelCategory`,
    `SimplicialSet`.
  - stable model structure, stabilization: NOT scheduled until the
    model-category API audit (see work items) says the ground holds.
- FIRST SHARDS: none until the F7/F8 depth audits return; do not pour
  concrete into an unaudited hole.

### F13. Combinatorial game theory — green-field, with a caveat

- NEEDED-BY: the dictionary itself (motives as game configurations; K/S/O
  tags as structure, not metaphor); partisan and loopy theory.
- NAIVE FORM: game values as ordinals assigned to set-theoretic trees;
  loopy theory as infinite trees with point-set loop conditions.
- RIGHT HOME: partizan games as an inductive type with universal-property
  values (order-theoretic, `PGame` in the literature sense); loopy games
  via the Siegel/ONAG framework where values live in a larger ordered
  algebraic structure; nimbers/surreals as quotients. The right home for
  the dictionary is the CONFIGURATION CATEGORY first, value extraction
  second.
- EXTRACTION: the numeric value theorems; Sprague–Grundy as a corollary of
  the impartial structure.
- MATHLIB: ABSENT at the pin (BRONZE+SILVER: scoped searches
  `PGame`, `Nimber`, `surreal` — 0 hits; the pinned
  `Mathlib/SetTheory` listing has no `Game/` directory). CAVEAT
  (recorded per protocol rule 4): unscoped searches hit
  `Mathlib/SetTheory/Game/PGame.lean` in fork checkouts — the ground is
  staked in fork-land; an in-flight upstream PR check is a mandatory work
  item before we stake API names.
- MINIMAL API (names TENTATIVE pending the in-flight check):
  - `Mathlib/SetTheory/Game/PGame.lean` — partizan games, the order.
  - `Mathlib/SetTheory/Game/Surreal.lean` — the value structure.
  - `Mathlib/SetTheory/Game/Nimber.lean` — impartial games, nim-addition.
  - loopy theory: predicted `Mathlib/SetTheory/Game/Loopy.lean` (anchor:
    Siegel, *Combinatorial Game Theory*, 2013, loopy chapters).
- FIRST SHARDS: the in-flight check; then the `PGame` order axioms,
  statement-only (Tier 1) — the cheapest green-field shard in the map.

### F1, F2, F3, F11 (MATURE/PARTIAL-MATURE): boundaries suffice today

- Sites and sheaves (1-categorical), schemes with smooth/étale morphisms
  and descent, the AG site layer (étale/Zariski/fpqc/proétale, points,
  representability, pretopologies), rigid/closed/braided monoidal
  categories: all usable as-is. Evidence SILVER (listings) + BRONZE
  (scoped searches); depth checks below.
- F5 algebraic cycles: a single `Basic.lean` (BARE); the cycle-layer shard
  program waits on the depth audit.
- F7 triangulated: real directory (203 scoped hits), bare-bones per the
  program's standing assessment; depth audit pending.
- F14 algebraicity/transcendence: algebraicity machinery is rich
  (`TranscendentalSeparable`, `FinTrdeg`, `IsAlgClosed`,
  `IsRealClosed`, `AxGrothendieck`, Galois); transcendence THEOREMS at
  points are thin — consistent with the Apéry program's own Section 62
  audit (Lindemann scaffolding; π-transcendence external; Baker
  roadmapped; Siegel–Shidlovsky unformalized anywhere). The certificate
  line stays classical per its proof obligations.
