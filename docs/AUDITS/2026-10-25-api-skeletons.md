# API skeletons: the nuts-and-bolts picture (2026-10-25)

The module map at the level of *foundational signatures*: not the headline
theorems but the type signatures, names, arrows, and constructions on
which each topic's proofs will actually hang. This is a PICTURE, not
code: signatures are planned shapes, to be staked per-shard after the
audit grades they rest on are GOLD. Anchors name the literature where the
object and its name come from. Dependency grades cite
`docs/AUDITS/2026-10-25-depth-audit-round1.md`.

## Line A — CGT upper layers (on top of `combinatorial-games`)

Substrate: the external Apache-2.0 `vihdzp/combinatorial-games` library
(BASIC layer: `Game`, `Game.Order`, `Game.Impartial`, `Game.Loopy`,
`Nimber`, `Surreal` — depth-audit item 5). Our modules add the layers it
provably lacks (no `therm|cool|misere|temperature|mean` in its tree).
Everything below assumes a lake dependency on that library; the
outcome-class section is contingent on the pending GOLD read of
`Game/{Classes,Confusion,Stops,Special}.lean`.

### A1. Outcome classes as a first-class enum (contingent)

Anchor: Conway, *On Numbers and Games*, ch. 1–2 (outcome classes); Siegel,
*Combinatorial Game Theory*, ch. 1.

```lean
inductive PGame.OutcomeClass
  | left | right | first | second   -- L, R, N, P

def PGame.outcomeClass (G : PGame) : PGame.OutcomeClass
theorem PGame.outcomeClass_left_iff : G.outcomeClass = .left ↔ (le_zero G ∧ ...)
-- four iff-lemmas, one per class, each defined through `PGame.le`
-- (the external library's order), never through numeric values.
```

Why: the dictionary reads outcome classes, not values; the four iff's are
the only interface the rest of the program consumes.

### A2. Thermography and cooling (green-field, ours)

Anchor: Conway, ONAG, "thermographs"; Siegel, CGT, ch. 1 (left/right
stops), ch. 9? thermographs; Berlekamp–Conway–Guy, *Winning Ways*.

Foundational signatures:

```lean
-- Walls are piecewise-linear (affine on segments) with slopes in {-1, 0, 1};
-- a scaffold is the finite combinatorial data of a wall.
structure Scaffold where
  segments : List (ℝ × ℝ)      -- (slope-intercept anchor) *picture only*

def PGame.cool (t : ℝ≥0) (G : PGame) : PGame          -- G_t, "cooling by t"
def PGame.temperature (G : PGame) : ℝ≥0∞              -- the largest t where G_t changes
def PGame.leftStop (G : PGame) : Surreal               -- G^L-stop
def PGame.rightStop (G : PGame) : Surreal
def PGame.mean (G : PGame) : Surreal                   -- the value of G_∞
structure Thermograph where
  leftWall : Scaffold
  rightWall : Scaffold
def PGame.thermograph (G : PGame) : Thermograph
```

The load-bearing lemmas (the API others build on):
`cool_add` (`(G + H)_t = G_t + H_t`), `temperature_lt_iff`,
`thermograph_cool_eq` (the thermograph of `G` is the union of the
thermographs of its options — the recursive characterization),
`mean_cool` (`G_∞ = mean G`). These four are the entire interface the
dictionary and the Todd/thermograph conjecture (trove T3) need.

### A3. Misère quotients (green-field, ours)

Anchor: Plambeck–Siegel, *misère quotients* (2008); Siegel, CGT ch. 12.

```lean
structure MisereQuotient (Γ) where
  Q : Type*            -- a commutative monoid
  [CommMonoid Q]
  φ : Positions → Q    -- the quotient map
  outcome : Q → MisereOutcome   -- the outcome depends only on the class
  -- universal property: any other such factorization factors through φ
```

The nuts-and-bolts here are NOT the quotient objects (finite, computed)
but the indistinguishability relation that generates them:
`misereIndistinguishable (G H : Position) : Prop` — the congruence
`≈` of misère play. First shard: the relation and its proof that it is a
congruence for disjoint sum (statement-only, then peel).

## Line B — Nisnevich via cd-structures

Substrate: `CategoryTheory.Sites` (MATURE — 70 files), in particular
`GrothendieckTopology.MayerVietorisSquare` (GOLD-read:
`structure MayerVietorisSquare extends Square C` with `SheafCondition`,
plus the free-abelian short-complex machinery). Anchor: Voevodsky,
*cd-structures and Nisnevich topologies* (2010).

```lean
-- B1. cd-structures as data (candidate CategoryTheory module)
structure CategoryTheory.CdStructure (C : Type*) [Category C] where
  squares : Set (CategoryTheory.Square C)
def CategoryTheory.GrothendieckTopology.ofCdStructure
    (D : CdStructure C) (hD : D.IsComplete) (hD' : D.IsRegular)
    (extra) : GrothendieckTopology C
theorem CategoryTheory.ofCdStructure_sieve_mem_iff   -- sieve membership
    -- characterization: the topology generated by the squares

-- B2. Nisnevich squares on schemes (candidate AlgebraicGeometry module)
structure AlgebraicGeometry.IsNisnevichSquare
    (sq : Square (SchemeOver S)) extends GrothendieckTopology.MayerVietorisSquare _ where
  etale : Etale sq.f         -- the top arrow is étale
  isoOnComplement : ∀ x, IsIso ... -- over every point of the open
                                    -- complement, sq.f is an iso
def AlgebraicGeometry.nisnevichCdStructure (S : Scheme) :
    CdStructure (SchemeOver S)
def AlgebraicGeometry.nisnevichTopology (S : Scheme) :
    GrothendieckTopology (SchemeOver S)
```

The two lemmas everything downstream needs: `nisnevichTopology_eq_ofCdStructure`
(the Nisnevich topology is the cd-topology of distinguished squares) and
`nisnevichSquare_iff` (the point-set criterion, as a *corollary*, per the
right-home analysis of the foundation audit).

## Line D — transcendence certificate line (statement layer)

Substrate: `RingTheory/AlgebraicIndependent/TranscendenceBasis` (MATURE),
`NumberTheory/Transcendental/Lindemann/AnalyticalPart` (analytical
skeleton present, main theorem unassembled), `FieldTheory` (algebraicity
MATURE). The gaps are the named theorems: Lindemann–Weierstrass (assemble
from the existing analytical part), Gelfond–Schneider, Baker,
Siegel–Shidlovsky — each is a `conjecture`-labeled statement in the lab
first (per the sorry law), with its literature reference and falsifier,
then peeled. The certificate line for the Apéry program composes:
`IsTranscendenceBasis.mvPolynomial` (the universal property) is the
arrow that converts transcendence-degree bookkeeping into polynomial
statements — the single most load-bearing existing signature for our
purposes, read GOLD.
